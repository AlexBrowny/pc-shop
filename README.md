# PC Market

Интернет-магазин комплектующих для ПК. Этап 1: каталог, конструктор с проверкой совместимости, расчёт FPS, RU/UZ, суммы в UZS, светлая/тёмная тема.

## Запуск

```bash
npm install
neon deploy        # один раз: создаёт бакеты и записывает DATABASE_URL, AWS_* в .env
npm start          # http://localhost:3000 (при старте применяются миграции, пустая БД заполняется каталогом)
npm run build      # проверка проекта: синтаксис всех JS, миграции, neon.ts
npm test           # юнит-тесты + интеграционные тесты против Neon
npm run migrate    # только применить SQL-миграции
npm run seed       # наполнить пустую БД (каталог, игры, иллюстрации)
npm run seed:reset # СТЕРЕТЬ каталог и заказы и заполнить заново (осторожно: на production удалит заказы)
npm run images     # перегенерировать иллюстрации и загрузить их в Neon Object Storage
```

Нужен Node.js ≥ 22.13. Курс для цен: `USD_RATE=12500 npm run seed:reset` (сум за 1 $).

## Neon: база данных и файлы

- **Postgres** (`DATABASE_URL`) — каталог, игры, заказы, настройки. Драйвер `pg`; приложение — долгоживущий Node-процесс, поэтому пул соединений переиспользуется и идёт через pooled-строку. Миграции (`server/migrations/*.sql`) выполняются по прямой строке `DATABASE_URL_UNPOOLED` под advisory-блокировкой. Остатки списываются в транзакции с `SELECT … FOR UPDATE` — два одновременных заказа на последний товар не уведут склад в минус.
- **Object Storage** (бакеты объявлены в `neon.ts`, доступ через Files SDK, переменные `AWS_*`):
  - `receipts` (private) — чеки об оплате. Ключ в БД, наружу не отдаётся; админ получает файл через `/api/admin/orders/:id/receipt`, в Telegram чек уходит из хранилища.
  - `media` (private) — иллюстрации товаров и обложки игр. Приложение отдаёт их по `/img/products/…` и `/img/games/…` (проверка имени, ETag, кэш), поэтому адреса картинок в БД не зависят от ветки Neon.
- Тесты работают на реальном Neon, но изолированно: отдельная схема `pcm_test_<id>` и префикс ключей `test-<id>/`, после прогона всё удаляется.
- Ветки: `neon checkout <имя> --create` создаёт копию БД **и** файлов для разработки или превью.

## Структура

- `data/products.js`, `data/games.js` — стартовый каталог (78 товаров) и 50 игр
- `server/lib/compat.js` — правила совместимости; `server/lib/fps.js` — модель FPS
- `server/routes/` — REST API (`/api/products`, `/api/builder/options`, `/api/builder/evaluate`, …)
- `public/` — фронтенд (vanilla JS, hash-маршруты, `i18n.js` — словари RU/UZ)

## Дизайн (в стиле приложения-конструктора)

- **Оболочка:** левая сворачиваемая панель (разделы, категории, «+ новая сборка»), верхняя панель с быстрым поиском (`Ctrl/⌘+K` или `/`), язык, тема, корзина. На телефоне панель становится выдвижным меню.
- **Главная:** «герой» с живой 3D-сборкой (авто-вращение) и стеклянной карточкой итогов, «Готовые сборки» (4 пресета из `data/presets.js`, цена и средний FPS считаются на сервере), бенто-сетка возможностей, «чертёжные» рамки и штриховка.
- **Конструктор:** плашки статуса (сумма · совместимость · потребление/БП · средний FPS), большая 3D/2D-панель с плавающей панелью инструментов и зумом, вкладки «Детали / FPS», строки деталей с кнопками «Выбрать / Заменить», окно выбора с фильтрами слева (только совместимые, в наличии, цена, производитель) и сеткой карточек справа.
- Палитра — графит + оранжевый + циан (переменные в начале `public/css/style.css`).

## Дизайн и анимации

- Палитра: графит + «ember»-оранж (`#ff6a1f → #ffb02e`) + циан для подсветки; светлая тема — тёплая «бумага». Цвета — CSS-переменные в начале `public/css/style.css`.
- Шрифты Unbounded (заголовки) и Manrope (текст) отдаются локально из `node_modules` (`/vendor/fonts`), кириллица включена.
- Анимации (`public/js/motion.js` + CSS): появление блоков при прокрутке, счётчики, наклон «героя» и подсветка карточек под курсором, ripple на кнопках, плавная смена темы и страниц, скелетоны загрузки, пульс бейджа корзины, вспышка изменённого слота и «растущие» полоски FPS. При `prefers-reduced-motion` всё отключается.
- Картинки товаров (`server/lib/art/*`, `npm run images`) — детальные векторные «рендеры» по категориям: форма и состав зависят от характеристик (число вентиляторов видеокарты по длине, слоты DIMM/M.2/SATA на плате, размер радиатора СЖО, форм-фактор корпуса и т. д.). Вентиляторы и RGB анимируются внутри самих SVG.

## 3D / 2D предпросмотр (этап 2)

- `public/js/viewer/` — three.js (из `node_modules`, раздаётся как `/vendor/three`): `layout.js` — чистая геометрия (покрыта тестами), `case-model.js` — полная модель корпуса, `parts.js` — детали, `viewer.js` — сцена, камеры, подписи.
- Размеры корпуса берутся из его характеристик (макс. длина GPU, высота кулера), плата/БП/СЖО/накопители ставятся по реальным форм-факторам и размерам выбранных товаров.
- Режим 2D — ортогональный вид сбоку с подписями деталей. Есть стеклянная стенка вкл/выкл, автовращение, полный экран, светлая/тёмная тема.
- Модели: все 3D-модели строятся кодом (процедурные меши, canvas-текстуры, RGB-подсветка с bloom) — внешние файлы не нужны.

## Заказы, чеки и Telegram (этап 3)

**Оформление:** корзина → «Оформить заказ» → имя, телефон (+998…), адрес, **чек об оплате (PNG/JPG/WEBP или PDF до 10 МБ)** → заказ.
Реквизиты для оплаты (карта, получатель, примечание RU/UZ) покупатель видит на этой странице; задаются в `.env` или в админке.

- Цены и остатки сервер берёт из БД, цены из браузера игнорирует; остаток списывается в транзакции, при отмене заказа возвращается.
- Тип файла чека определяется по содержимому (не по расширению), чеки лежат в приватном бакете Neon Object Storage `receipts` и **не отдаются публично** — только админу.
- После сохранения заказа бот присылает менеджеру сообщение с составом/контактами и файлом чека (фото или документ).
  Если Telegram недоступен, заказ всё равно сохраняется, в админке виден статус и кнопка «Отправить повторно».

**Настройка Telegram**
1. Создайте бота у @BotFather, токен вставьте в `.env` → `TELEGRAM_BOT_TOKEN`.
2. Менеджер открывает бота и нажимает Start (для группы — добавьте бота в группу и напишите сообщение).
3. `npm run telegram:chat-id` покажет Chat ID → впишите его в `.env` (`TELEGRAM_CHAT_ID`) или в админке → «Настройки».
4. В админке → «Настройки» → «Отправить тестовое сообщение».

## Оплата картой (Stripe)

На чекауте покупатель выбирает: **карта онлайн** (Stripe Checkout) или **перевод на карту + чек** (как раньше). Если `STRIPE_SECRET_KEY` не задан, остаётся только оплата по чеку.

1. Заказ создаётся со статусом «Ждёт оплаты» (`pending`), товар резервируется, покупателя перенаправляет на страницу Stripe.
2. Деньги списываются в **долларах** по курсу `USD_RATE` (сумы Stripe принимает не во всех странах аккаунта).
3. Stripe присылает вебхук `POST /api/stripe/webhook` (подпись проверяется по `STRIPE_WEBHOOK_SECRET`): заказ становится «Оплачен», менеджеру уходит уведомление в Telegram (чек не нужен). Повторные вебхуки безопасны.
4. Если оплата не прошла или сессия истекла (30 минут) — заказ отменяется, товар возвращается на склад. Страница «Оплата прошла» сама сверяется со Stripe, поэтому работает, даже если вебхук задержался.

Настройка: ключи — Stripe Dashboard → Developers → API keys; вебхук — Developers → Webhooks → Add endpoint, URL `https://<домен>/api/stripe/webhook`, события `checkout.session.completed`, `checkout.session.expired`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`. Для локальной проверки: `stripe listen --forward-to localhost:3000/api/stripe/webhook`. Тестовая карта: `4242 4242 4242 4242`, любой срок в будущем и CVC.

## Аккаунты, отзывы, фильтры, сравнение

- **Покупатели:** регистрация и вход по email + пароль (пароли хешируются scrypt, сессия — подписанная HttpOnly-cookie на 30 дней, изменяющие запросы защищены заголовком `X-Requested-With`). Подтверждения email и восстановления пароля пока нет — для них нужна почтовая служба.
- **Личный кабинет** (`#/account`): история заказов (заказы вошедшего покупателя привязываются автоматически), сохранённые сборки, ссылка «Поделиться».
- **Сборки:** «Сохранить» в конструкторе (нужен вход) и «Поделиться» — ссылка вида `#/builder?b=cpu.12~gpu.44~storage.3.4` открывается у кого угодно без входа.
- **Отзывы и рейтинг:** оценка 1–5 и текст, один отзыв на товар; значок «Покупатель» у тех, кто купил товар (заказ оплачен/отправлен/завершён). Модерация — вкладка «Отзывы» в админке (скрыть/показать/удалить).
- **Фильтры каталога:** бренд, цена, наличие, рейтинг и характеристики категории (сокет, ядра, тип памяти, объём, форм-фактор и т. д.). Варианты берутся из реальных данных (`GET /api/filters?category=…`), список разрешённых ключей — `FILTER_SPECS` в `server/lib/specs.js`.
- **Сравнение:** до 4 товаров одной категории, отличия подсвечиваются (`#/compare`).
- **Фото товаров:** вкладка «Фото» в админке — счётчик «настоящих фото», загрузка пачкой (товар подбирается по имени файла: `rtx-4070-super.jpg` → главное фото, `rtx-4070-super-2.jpg` → в галерею), быстрая замена главного фото и импорт по ссылке (только https, внутренние адреса запрещены, тип проверяется по содержимому). Пока у товара нет фото, показывается иллюстрация. Карточки в стиле маркетплейса: настоящие фото на светлой подложке, второе фото при наведении, увеличение на странице товара. До 8 дополнительных фото на товар. Используйте только фото, на которые у вас есть права (материалы поставщика, собственные снимки).
- **Игры для FPS:** 50 встроенных (при запуске сервера недостающие добавляются автоматически, `npm run seed` делает то же).

## Админка `/admin`

Скрыта: нет ссылок с сайта, закрыта от индексации (`X-Robots-Tag`, `noindex`), своя строгая CSP. Вход — логин `ADMIN_USER` / пароль `ADMIN_PASSWORD` из `.env`
(если пароль не задан, при первом запуске генерируется случайный и показывается в консоли один раз; хранится только хеш scrypt).

- Сессия — серверная, cookie `HttpOnly` + `SameSite=Strict`, 8 часов; для изменяющих запросов нужен заголовок `X-Admin-CSRF`; 5 неудачных входов за 15 минут блокируют IP.
- **Заказы:** список, фильтры, карточка с чеком, смена статуса (новый → оплачен → отправлен → завершён / отменён), заметка, повторная отправка в Telegram.
- **Товары:** добавление и редактирование с формой характеристик по категории (по ним работают совместимость, FPS и 3D), загрузка картинки (SVG не принимается); без картинки создаётся иллюстрация. «Удаление» скрывает товар с витрины.
- **Игры:** добавление игр в базу FPS (требовательность к GPU/CPU/VRAM по 4 пресетам), обложка загружается или генерируется.
- **Настройки:** Chat ID, реквизиты оплаты, тест Telegram.
